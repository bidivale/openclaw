# Summary

you don't run docker compose build at all, and you don't need to create a .env file manually.
Here's why:
./docker-setup.sh is the all-in-one entry point that does everything in order for you. The script builds the gateway image locally, runs the onboarding wizard, starts the gateway via Docker Compose, and generates a gateway token — writing it to .env automatically.

## correct order

### 1. Clone the repo (already done)

git clone ...
cd openclaw

### 2. Run this ONE script — it handles everything

./docker-setup.sh

That's it. The script will:

Build the Docker image (the docker compose build step)
Run the interactive onboarding wizard (where you enter your API keys)
Generate and write OPENCLAW_GATEWAY_TOKEN to .env
Start the gateway

The only reason you'd create a .env yourself beforehand is if you want to pass optional flags like OPENCLAW_IMAGE (to skip building and pull a pre-built image instead) or OPENCLAW_SANDBOX=1. For a first-time standard setup, you need nothing pre-created.

# What we need during ./docker-setup.sh run ?

The Only Hard Requirement: One AI Model Key
You need exactly one thing before running ./docker-setup.sh: an API key for at least one AI model provider. Channels like Telegram are optional during onboarding — you can add them later.

Yes, Your Mistral Free Key Works — No OpenAI Compatibility Needed. Put it when asked.

Telegram: Optional at Onboarding, Easy to Add Later
You can skip Telegram entirely during ./docker-setup.sh and add it afterwards. The config is just a botToken in openclaw.json:
jsonchannels: {
telegram: {
enabled: true,
botToken: "your-bot-token"
}
}
Same applies to WhatsApp or any other channel — each channel has its own config section under channels.<provider>, and you configure them independently on the dedicated channel page. Openclaw None are required to get the gateway running.

The Onboarding Command for Your Setup
When docker-setup.sh launches the wizard, choose Mistral as your provider and paste your key. That's all you need for a working gateway on day one. Telegram and WhatsApp can be wired in afterwards whenever you're ready.

# environment in docker-compose explained

The 5 Environment Variables Explained

1. OPENCLAW_GATEWAY_TOKEN ⚠️ Required
   This is the bearer token used to authenticate access to the OpenClaw gateway Control UI. GitHub Think of it as the "password" to your OpenClaw web dashboard at http://127.0.0.1:18789.
   You don't set this manually. It's auto-generated and persisted during setup — if you run ./docker-setup.sh, it generates the token and writes it to .env automatically. Openclaw After setup, you paste it into the dashboard at Settings → Token.
   If you're running manually without docker-setup.sh, you need to generate one yourself (any random secure string works) and put it in .env.

2. OPENCLAW_ALLOW_INSECURE_PRIVATE_WS — Optional, leave blank
   This is a "break-glass" flag: setting it to 1 allows trusted private-network ws:// (non-secure WebSocket) targets for CLI/onboarding paths. The default is loopback-only. Openclaw
   Leave this empty unless you have a specific advanced networking setup that requires it. It's not a credential — it's a security toggle.

3–5. CLAUDE_AI_SESSION_KEY, CLAUDE_WEB_SESSION_KEY, CLAUDE_WEB_COOKIE — Optional, leave blank
These are not your primary AI credentials. They're supplementary and only used for one narrow purpose: usage tracking — showing your Claude plan usage in /status. The setup-token onboarding flow only requests user:inference scope, while usage tracking requires user:profile scope, which is only granted via a full browser OAuth flow. The fallback to a claude.ai web session key requires a separate env var most users won't have. GitHub
In plain terms: you don't need these to use OpenClaw at all. They only matter if you want to see your Claude subscription usage stats inside OpenClaw's dashboard. Leave them empty.
